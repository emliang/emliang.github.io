Suppose a model helps divide a one-unit budget between two services. It predicts 0.51 units for each, close to a reference allocation of 0.5 each. The prediction error is small, but the total exceeds the budget. Learning useful allocations means respecting that limit as well as predicting accurately.

Robot routes must clear obstacles; generated molecules must obey structural rules. The budget problem captures the same distinction between a plausible proposal and a usable output. It also extends naturally from predicting one allocation to generating several alternatives.

Accurate, yet impossible to use

Whether the returned allocation strictly fits the budget rule.
Utility

A near-reference allocation can exceed the budget; a zero allocation is feasible but of little use.

Draw the feasible set first

The point (0.8,0.8)(0.8,0.8)(0.8,0.8) sits outside this triangle. The points (0.4,0.4)(0.4,0.4)(0.4,0.4), (1,0)(1,0)(1,0), and (0,0)(0,0)(0,0) lie inside or on its boundary. Feasibility alone does not say which allocation best serves the task.

A feasible set can combine equalities, such as conservation laws, with inequalities, such as capacity limits. It may also depend on today’s demand, the current robot state, or a requested output schema. Write this instance-dependent set as KxK_xKx​, where xxx describes the instance. The requirement applies to the returned yyy, after any decoding, completion, correction, or solve.

A hard requirement determines which outputs are admissible. For the triangle, all three inequalities must hold. Numerical implementations check equality and inequality residuals against stated tolerances.

Can we just add a penalty?

A constraint penalty makes violations expensive during training. Added to the task loss, it can supply constraint information even when feasible labels are scarce. DL2, for example, translates logical specifications into losses optimized with gradient methods.[1]

The penalty weight sets the trade-off between task loss and violation. The result also depends on the model, data, optimization accuracy, and aggregation: a small average violation can conceal a few allocations that exceed the budget.

Consider a pointwise quadratic penalty: stay near the preferred allocation y^\widehat{y}y​ = (0.8,0.8)(0.8,0.8)(0.8,0.8), while penalizing an exceeded budget:

This persistent violation comes from the quadratic penalty in this example; exact-penalty methods can recover feasible optima under suitable conditions. A training penalty also needs a separate argument to establish feasibility of a learned predictor’s outputs. Output construction and correction offer other ways to enforce the rule.

Four families of constraint handling

Constraint handling can act during training, within a network layer, through the output representation, or after prediction. Our survey organizes these roles into four families: training-based approaches, structured NN layers, constraint parameterization, and post-processing.

Training-based approaches: change the predictor

  • Mechanism: shape the training loss, constrained learning objective, or a verification-guided model update so the predictor runs directly at inference.[2][3]
  • Watch out: improving average violation is not the same as certifying feasibility for every input in a specified region.

Structured NN layers: train through an output operation

  • Mechanism: append a layer that transforms predictions, completes missing variables, or solves a constrained optimization problem, then backpropagate task loss through it (or a backward approximation).
  • Examples & trade-off: OptNet and differentiable convex optimization layers supply feasibility up to solver tolerance while letting the network anticipate the layer’s effect.[4][5]

Constraint parameterization: use a feasible representation

  • Mechanism: build feasibility into the output coordinates—via convex combinations of feasible generators (e.g., ConstraintNet over input-dependent polytope vertices[6]), feasible distributions, or gauge maps from a bounded reference domain (see Homeomorphism Methods[7]).
  • Watch out: coverage matters (a valid parameterization may exclude good solutions), and the final operation still matters (averaging feasible points can exit a nonconvex set).

Post-processing: recover the returned output

  • Mechanism: apply projection, geometry-specific recovery, or a warm-started solver after prediction without training through it.[8]
  • Practice & latency: in large-scale tasks like AC optimal power flow, choosing between an iterative solver layer and fast coordinate-based recovery often decides real-time feasibility.

These families can also be combined—for example, DC3 pairs equality completion with differentiable inequality correction[9]—though later stages can undo earlier guarantees. See the prediction guide on GitHub ↗ for method-level details.

From constrained prediction to constrained generation

The same demand may admit several useful allocations: one favors the first service, another the second, and a third leaves some budget unused. Rather than commit to one prediction, a generative model uses random inputs to propose alternatives, optionally conditioned on that demand and task context.

Each sample must still fit the budget. We also care about which allocations appear, and how often. A correction can make every sample feasible while concentrating them on a few allocations. Generation therefore requires attention to diversity and coverage as well as sample quality, and to fidelity when the task specifies a target distribution.

Direct generation
Produces a complete candidate in one shot (including distilled iterative models), so prediction mechanisms can be reused directly.
Autoregressive generation
Builds candidates through successive choices; a grammar can restrict each step,[10] but a locally valid prefix may still admit no valid completion.
Diffusion & flow
Focus here
Refines a sampling state ztz_tzt​ over generation time ttt via learned denoisers, scores, or velocity fields before returning yyy.

Repeated updates create several places to impose constraints: the current state, an estimate of the completed sample, or the final output. These objects need not satisfy the same requirements.

Constraint handling in diffusion and flow models

For an iterative allocation generator, the budget rule applies to the completed allocation; noisy intermediate states need not satisfy it. In trajectory generation, each update similarly revises a candidate route. Generation time describes the sampler’s progress, distinct from physical time along the route.

Valid samples can still follow different distributions

Take the uniform distribution over the allocation triangle as the target. Draw proposals uniformly from [−1,1]2[-1,1]^2[−1,1]2 and compare two ways to obtain feasible samples.

Rejection keeps feasible draws from the uniform square; independent draws and an exact membership test give the conditional target, with population acceptance 18\tfrac1881​. Projection returns feasible outputs from every proposal, but places population mass 78\tfrac7887​ on the boundary, including 14\tfrac1441​ at the origin. Thus full feasibility does not imply the desired distribution. This experiment isolates an output operation, with no trained diffusion or flow model. The same issue arises in those samplers: constraint handling can change the distribution of returned samples.

For diffusion and flow models, our survey groups constraint handling into four overlapping viewpoints: training-based methods, geometry-aware sampling, constraint parameterization, and guidance, correction, and search.

  • Geometry-aware: Reflected Diffusion and Riemannian Flow Matching keep dynamics on the target domain or manifold.[11][15]
  • Guidance & correction: Universal Guidance steers sampling with an objective,[12] while Projected Diffusion and Physics-Constrained Flow Matching apply corrections at different points in the loop.[13][14]
  • Search: evaluates and selects continuations without requiring differentiable objectives.

Combining mechanisms

Training can anticipate a sampling correction, while different stages handle complementary requirements. Their order matters: output-space guidance can move a decoded sample outside the feasible set. Guiding within admissible coordinates or correcting for the combined requirements can avoid this conflict. Choose from the operations you have

In the triangle example, projection ensures feasibility but changes the target distribution; rejection preserves that distribution but discards proposals. The choice depends on the required outcome—feasibility of each sample, a population statistic, or a sampling-process property—and on the operations available for the task.

Include preparation costs: building a feasible representation may require vertex enumeration or a reference-point solve. A model used as a solver warm start should save time over a conventional initialization at the same stopping tolerance.

When the same constraints recur, training or preprocessing costs can be spread across many queries. When constraints change, online construction and enforcement matter more.

Evaluate the result you will actually use

Evaluate the complete procedure, including any decoding or repair, along four dimensions:

01

Constraint satisfaction

Does every output pass?
  • Metrics: report pass rate and maximum equality/inequality residuals at stated tolerances, not population averages alone.
  • Evidence: specify whether feasibility comes from construction, a solver, a certificate, or empirical evaluation.
02

Output quality

Is it useful & diverse?
  • Prediction: pair reference accuracy with downstream decision utility.
  • Generation: assess sample quality, diversity, coverage, and fidelity to any target distribution.
03

Computational cost

What is true end-to-end cost?
  • Full pipeline: measure preprocessing, training, checks, decoding, correction, rejected draws, and solver calls.
  • Generation: report cost per valid sample rather than per raw draw.
04

Applicable scope

Where do guarantees hold?
  • Assumptions: state required constraint geometry, input region, oracle, and solver conditions.
  • Discretization: if feasibility holds in continuous time, verify how numerical steps preserve it.

If a solver repairs a prediction, measure the repaired decision’s quality and the complete latency. If a relaxation is rounded, check the rounded output against the original constraints. Later stages can invalidate an earlier feasibility guarantee.

Prediction asks for a useful allocation that fits the budget. Generation also asks for the right collection of alternatives. Feasibility, quality, distribution, and cost belong in the same comparison.
